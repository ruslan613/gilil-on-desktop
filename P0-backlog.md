## P1 (после P0)

1. **Синхронизация папки на ПК** — локальная папка на компьютере пользователя автоматически синхронизируется с сервером (загрузка/удаление файлов в обе стороны), файлы доступны в программе команде RU/CN, бэкап на сервере. Реализация: Electron-приложение следит за папкой (`fs.watch`), загружает изменения через API, показывает статус синхронизации в UI.
2. **Настраиваемое левое меню** — разделы перетаскиваются, скрываются, порядок сохраняется; pill-вкладки сверху заменить или дополнить левым меню.
3. **Стартовый раздел** — пользователь выбирает раздел, который открывается при запуске приложения, настройка сохраняется в профиле.
4. **Календарь** — раздел календаря в программе (встречи, дедлайны задач, дедлайны тендеров), синхронизация с задачами и чатами, напоминания.
5. **Уведомление о смене адреса входа** — при логине с нового IP/геолокации (не совпадает с последним известным) — алерт админам через колокольчик уведомлений и трей/пуши Electron; показывать IP, город/страну, время; хранить историю адресов входа в SQLite.
6. **Журнал активности сотрудников** — сервер логирует входы/выходы, длительность сессий, действия (чаты, задачи, счета, разделы, шаги воронки заказа); хранение в SQLite. Директор/генерал-админ видит по каждому сотруднику: текущий этап работы, время в программе, чем занят. **Админы-руководители** — только своих подчинённых; сотрудники журнал **не видят**. → **Программа (этап 2)**
7. **Ролевая модель: три уровня** — генерал-админ (все ключи, полный доступ, видит всё: журнал активности всех, все цены RU+CN), админы-руководители (видят своих подчинённых и журнал их активности, цены только своего региона), сотрудники (только своё). Реализация: JWT-роли с уровнями, проверка прав на сервере при каждом запросе.
8. **Защита от взлома** — все проверки ролей и прав только на сервере (JWT + серверная валидация при каждом запросе, клиент не доверяется); защита от подмены токена; ограничение попыток входа (rate limit, блокировка после N неудачных); журнал попыток несанкционированного доступа (попытка зайти на чужой уровень, чужой IP) — виден только генерал-админу; скрытые данные (цены другого региона, чужие хранилища) не отдаются клиенту даже при прямом запросе API; шифрование переписки AES-256; запрет обмена контактами в обход программы.
9. **Воронка обработки заказа** — письмо/заказ проходит шаги: прочитано → найти поставщиков → первая спецификация → сравнение цен с конкурентами → отправка клиенту; у каждого шага статус и исполнитель. Руководитель видит активность по заказу: кто, когда, что сделал, где застряло. Расширение журнала активности, привязанное к заказу (не к входам в систему).
10. **Коэффициент полезности сотрудника** — авторасчёт по активности: время в программе, шаги воронки (прочитано → поставщики → спецификация → цены → клиенту), скорость ответов, выполненные задачи. Директор может вручную скорректировать оценку и оставить комментарий. Панель директора: сводка по всем, рейтинг, алерты по простоям и отставанию от воронки. Сотрудники свой коэффициент и чужую активность **не видят** — только директор/генерал-админ. → **Программа (этап 2)**
